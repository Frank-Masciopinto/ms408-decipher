# Hybrid generators: plaintext dependence + copy-and-modify word reuse vs MS 408

_Auto-generated by `python -m msdecipher hybrid-run`. **MS 408 is undeciphered.** These generators are tests of whether combining two published ingredients repairs the metrics each parent misses; a reproduced metric shows that metric does not discriminate, not that the manuscript was made this way._

## 1. Design

Engine (`mech_hybrid.py`; a simplified Python copy-and-modify process, **not** the Timm & Schinner rule set): with probability `p_copy` copy a recent word (previous word with prob `p_prev`, else uniform over the last `window` words) and apply one operation (exact repeat `p_exact`, final-unit edit `p_suffix`, initial-unit edit `p_prefix`, inner-unit replacement = the rest); otherwise take the next word from the *encoder*. Max 3 identical repeats, ≤ 10 units. **6 fitted engine parameters.**

| id | encoder (the plaintext-dependent part) | extra fitted parameters |
|---|---|---|
| A1 | Naibbe cipher tokens produced on the fly from Latin/Italian plaintext (1–2 letters per innovation); edit units drawn from the innovated words' own unit distributions | 0 |
| A2 | whole-word codebook: every plaintext word type gets a fixed codeword sampled (invertibly) from a slot-conditioned-bigram grammar fitted on the *training types* | grammar parameters (counted) |
| B (reverse) | copy-modify base (`p_copy ≥ 0.6`); every edit inserts the Naibbe glyph string of the next plaintext letter (prefix / suffix / unigram state, table by card draw); innovations are Naibbe tokens | 0 |
| C0 (control) | same engine, innovations i.i.d. from the MS-fitted slot-conditioned-bigram grammar: **no plaintext** | grammar parameters (counted) |

## 2. Protocol

* 3 folds by folio (folio *i* → fold *i* mod 3): fit on two folds' text, evaluate on the third. 3 training sizes: 23,728, 22,938, 23,288 tokens.
* Fit objective: RMS z over 9 lexicon metrics + H1/h2/h3 (12 metrics); random search (120) + local refinement (3 × 30), 2 generator seeds per candidate; z-scale = sqrt(jackknife SE² + (2 % of value)²). **Every other suite metric (23) is never fitted.**
* Evaluation: best parameters, fresh seeds, 5 runs per model per fold (different plaintexts), generated at the held-out fold's size, full 35-metric suite, prediction-interval verdicts against the held-out fold (SE = delete-one-group jackknife).
* Parents under the same protocol: Naibbe (78-card), Timm-Schinner (defaults; and parameters fitted earlier on **all** MS 408 → in-sample, favours the parent), slot-conditioned bigram trained on the training folds. Naibbe-live (A1/B) and `NaibbeCipher` share tables and rules.

## 8. Limitations

* The engine is a **simplified** copy-and-modify process. The authors' Java generator has glyph classes, 'similar glyph' tables and follow rules designed after looking at Voynichese; this engine has none of them, so differences from the Java parent mix 'rules' with 'plaintext'.
* Free parameters vs metrics: 6 engine parameters against 12 fitted metrics (A1, B). A2 and C0 additionally use an MS-408-fitted grammar (~1.4k parameters) to draw words; their letter-level agreement is partly circular and must not be read as evidence for the plaintext ingredient. C0 (no plaintext) is the control for exactly this.
* Plaintext is only a source of dependence structure: plaintexts are Latin/Italian controls (not a conjectured MS 408 plaintext); with a codebook the plaintext word-frequency distribution passes through unchanged, with Naibbe tokens the plaintext only influences letter-pair statistics.
* 3 folds with interleaved folios share sections, Currier languages and scribal habits with the training folios; this tests generalisation across folios, not across sections or hands.
* Suite metrics are length-dependent; every comparison is made at matched size, but held-out folds are only ~11k tokens and have wide jackknife SEs (8 groups).
* A hybrid that fits is an *existence* result for a generator family; the parameters are not identified (see fit traces), and MS 408 remains undeciphered.
